## New staged agent-workflow contract
src/agent-workflow.ts is a pure transition module preparing a four-role chain:
1. creative (manusförslag)
2. research (frågor att verifiera; not factual verification)
3. quality (language and structure proposal)
4. manager (aggregated recommendation)

Each provider call is an independent opt-in step, requiring:
- explicit affirmative owner consent;
- known positive credit quote and an owner-approved positive upper bound;
- the exact current script revision and a unique call claim;
- a running claim recorded durably before any provider request;
- no automatic retry when a paid response may be uncertain.

The module itself performs NO provider calls, billing, uploads, publication or project edits.
A completed chain can only transition to awaiting_owner_review. It cannot approve content.

## Source-backed momentum ranking (GitHub only)
src/momentum.ts calculates *measured* views-per-hour when at least two valid YouTube
counter observations (>= 15 minutes apart, most recent <= 24 hours old) exist.
No data => no velocity score. src/manager.ts prefers this evidence before
falling back to recency/total views, with a clear explanation and optional
fields for existing plan backward compatibility. The UI surfaces the interval.
This is not a validated breakout predictor.

## No-cost Shorts pre-production planning (GitHub only)

30 fps scene and approximate caption timeline from a **saved** English script
(80–150 words, 3–8 paragraphs, hook 3–8 words). The UI under Videostudio is
collapsed by default and performs no provider calls.

- No media, voices, captions or MP4 files have been generated by this planner.

## Publication-safety architecture, private upload only
New `src/private-upload-gate.ts` is pure, with no network/YouTube calls.
It binds a completed operator-reviewed MP4 with SHA-256, file size, duration,
video format, audio present, caption and rights self-attestations, exact manuscript
revision, and authenticated owner identity.
Two distinct **human actions** are required:
1. exact final MP4 review, matching its SHA-256 and script revision;
2. a separate private-only upload authorization for an exact YouTube channel and
   upload title/description. No public release authorization is exposed.
Changing a manuscript revision, file bytes or channel invalidates the grant,
and revocation clears it. This is a preparatory contract, NOT wired to
AppDeploy, OAuth or YouTube. A later backend must verify identity via
server-side auth, compute SHA from actual stored bytes, maintain CAS transaction
state and use the immutable approved metadata. Rights self-attestation is not
independent legal verification. No uploaded file is safe solely because flags
were submitted.

## Local real AI agent chain (no AppDeploy credits)

The new `scripts/run_local_agents.mjs` is an opt-in CLI for four local
model inferences in order: creative -> research -> quality -> manager.
It uses Ollama POST /api/generate in JSON nonstream mode, but the endpoint
is fixed to 127.0.0.1:11434. No external AI service, model download, video
upload, scheduler, or paid AppDeploy API is invoked by this CLI.

Requires Node 22+, an Ollama server installed on your own computer,
an English-capable model already present on that computer, enough compute
and an acceptable model license. No model is installed by this repo or CI.

    node --experimental-strip-types scripts/run_local_agents.mjs \
      --topic "An original fictional story about gaming" \
      --source-url https://example.org/source \
      --model llama3.2:3b \
      --out-dir ./my-agent-draft \
      --allow-local-inference

The CLI writes agent-proposals-UNVERIFIED.json and source-DRAFT.json in a NEW
directory; both are unapproved drafts. Explicit --allow-local-inference
is required for each run. Agent inputs and prior proposals are untrusted.
Research does NOT browse or verify facts: it only lists facts to check.
The final original Short must pass the existing 80-150 words, 3-8
paragraphs and 3-8 word hook rule. Invalid outputs fail closed.

GitHub Actions tests use a MOCK inference implementation to check code
flow and safety, not a real local model. A real local inference has
NOT yet been conducted. No public-release feature or AppDeploy deployment
is enabled. Real integration still requires owner-scoped persistent
authorization, atomic retries, quality review and YouTube OAuth.

## Manual low-quota YouTube popularity discovery (GitHub-only)

src: `scripts/youtube_popular_discovery.mjs`. One manually authorized call to
official YouTube Data API v3 `videos.list` with `chart=mostPopular`
(documented by Google as 1 quota unit per request).
Set `YOUTUBE_API_KEY` in the local environment. Do not paste keys into
GitHub, source files, CLI options, saved logs, or a chat.

    YOUTUBE_API_KEY='YOUR_LOCAL_KEY' node scripts/youtube_popular_discovery.mjs \
      --region US --max-results 15 --out my-youtube-popular.json \
      --allow-one-api-call

**No call is made automatically** by this repository or CI.
Output contains video title, channel, publishing date, total views,
duration, and source URL. It deliberately makes no claims about:
- verified Shorts status (video length alone is insufficient);
- viral velocity or views/hour (one observation is insufficient);
- factual truth or re-use rights of any third-party video.

To measure velocity, a second real reading at a later time must be stored
and compared with actual timestamps. The existing pure momentum module
supports that later step. This collector currently performs ONE request
and writes ONE timestamped snapshot; it is not an autonomous radar.

## Offline YouTube observations → topic → four agents → MP4 (new)

The `scripts/youtube_candidate_radar.mjs` module consumes previously saved
YouTube popularity snapshots; it makes NO new API calls. It requires two
snapshots from the same region, 15 minutes to 24 hours apart, and compares
cumulative counts for the same video. Counter decreases, mismatched video
metadata and missing earlier observations are not treated as measured growth.
Single snapshots produce ONLY a popularity list, without an automated
growth-based suggestion. Two valid observations measure an interval-average
views-per-hour, NOT a verified virality trend or proof the video is a Short.

`scripts/run_saved_trend_to_preview.mjs` is a MANUALLY triggered bridge:
operator selects one exact video ID from the saved shortlist, explicitly
authorizes four local Ollama calls, and specifies a new output folder.
The selected video is only a TOPIC/reference; the source footage is NEVER
downloaded/copied by the pipeline. All facts, copyright rights, scripts,
subtitles, voice and publication permission remain unverified/unapproved.

Example after a local Ollama model has been installed:

    node --experimental-strip-types scripts/run_saved_trend_to_preview.mjs \
      --latest latest-popularity.json --earlier earlier-popularity.json \
      --video-id ABCDEFGHIJK --model llama3.2:3b \
      --out-dir ./unapproved-short-preview --silent-preview \
      --allow-local-inference

The separate collection step requires its own explicit consent and quota.
No YouTube collection or local neural inference has been run by CI.
CI uses two SYNTHETIC popularity snapshots and MOCK local-model outputs,
but FFmpeg renders an ACTUAL H.264 MP4 and verifies it on disk.
CI tests cover stale/mismatched snapshots, single-reading limitations,
manual choice and consent, without AppDeploy credits or YouTube API usage.
